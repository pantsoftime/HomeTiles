// Release flow (GitHub Actions builds and publishes automatically; see RELEASING.md):
//   1. Increase FW_VERSION below only when the current state is ready to release.
//   2. git commit  ->  git tag vX.Y.Z  ->  atomically push main and the tag
// Important: Only a tag push starts the build, and the tag must match FW_VERSION exactly.
//
// Fork line: upstream release tag + an extra patch digit (see README-FORK.md).
// Merge upstream RELEASE TAGS, not upstream's default branch (renamed
// master -> main on 2026-09-11).
//
// Upstream's patch is two digits from v0.6.10 on, so this reads oddly but still
// orders correctly: github_update.cpp parses each component with atoi(), giving
// {0,6,121} > {0,6,103}. Note v0.6.91 and later sort ABOVE upstream's v0.6.1x;
// only this fork's own releases are ever compared, so that is harmless.
//
// v0.7.01 is upstream v0.7.0 plus the patch digit; atoi() reads "01" as 1, so it
// parses as {0,7,1} and still sorts above every v0.6.x release.
#define FW_VERSION "v0.7.01"
